Engineering notes

The interesting part is underneath.

A few problems from my own projects, and what I changed to fix them.

Aures · Serving
3 s→300 ms

Static over serverless

Every resume request hit a serverless function that looked up the latest version in the database. Cold start plus lookup took about three seconds. I made the system rewrite the file whenever a resume changes and serve it statically. Paint time dropped to 300–500 ms.

Aures · PDF generation
5–6 s faster

One cold start, not two

PDFs came from a LaTeX compiler in a Docker container, so a request paid for the function's cold start and the container's. I ran a Linux build of the compiler inside the function, executed securely, so one function compiles and uploads. No extra resources.

UrbanScale → Locent · Scoring
Seconds→ms

Single-threaded to parallel

The location scorer began as Python, checking each amenity category in turn. I rewrote it in Node.js so every category is queried concurrently and the whole thing deploys serverless. Responses went from seconds to milliseconds, and cost fell with it.

Aures · AI import
Parse∥Rewrite

Splitting the LLM's job

Asking one model call to parse and rewrite a resume meant skipped sections and cut-off output. I split parsing and rewriting into separate calls running in parallel. It is faster and finishes reliably.
